# Translation-ready text: what is done and what is left

Status 2026-11-04. English ships in 1.0; Spanish is planned for 1.1.

## Done

- **One message catalog for the whole page**: `windlab/app/static/i18n/en.json`
  (`{"locale": "en", "messages": {key: text}}`, about 630 messages), keys grouped by step and section
  (`shape.*`, `preview.*`, `cond.*`, `run.*`, `res.*`, `sweep.*`, `slice.*`, `chart.*`, `tour.*`, `runs.*`,
  `compare.*`, `lesson.*`, `glossary.*`, `fb.*`, `msg.*`, `demo.*`, `viewer.*`, `plot.*`, and `page.*` for the
  fixed text of `index.html`), placeholders written `{name}`.
- **A tiny helper**, `windlab/app/static/i18n.js`: `t(key, params)` fills the placeholders (a missing key
  shows as `⟦key⟧`, a missing parameter stays visible as `{name}`); `nf(x, digits)` and `nfInt(x)` format
  numbers with `Intl.NumberFormat` for the catalog's locale. The catalog is loaded once at start-up from next
  to the module (the installed app and the static demo both find it; `scripts/build_static_demo.py` copies it).
- **Every message the scripts build** goes through `t()`: `app.js` from Step 1 to the end (shape, conditions,
  run, results, My runs, Compare, trial feedback, lessons, glossary, tour, About, the demo set-up, the
  "server not answering" messages), `preview.js` (the instant preview's notes, readout and descriptions),
  `viewer.js` (the 3D views' labels and hint), `chart.js` (live chart names) and `plot.js` (the centre-plane
  note). Wording is unchanged. Tables of fixed choices (run statuses, lesson step kinds, marker shapes) are
  tables of keys, so the scan below still sees every key.
- **The fixed text of `index.html`** is marked: every element whose content is plain text has
  `data-i18n="key"`; an element whose content is text with a little inline formatting (`<b>`, `<strong>`,
  `<sub>`, `<code>`, …) has `data-i18n` too and the message keeps that markup, which `richNodes()` in app.js
  turns into elements (never `innerHTML`); where a sentence is interrupted by a (?) glossary button or a
  value the script fills in, each run of text is wrapped in its own `<span data-i18n>` (so a translator sees
  the sentence in two or three pieces, in page order; the `page.*` keys are named after the nearest id);
  `aria-label` attributes have `data-i18n-attr="aria-label:key"`. The English stays in the markup as the
  fallback; `applyPageText()` replaces it from the catalog right after the catalog loads and sets
  `<html lang>` to the catalog's locale. The two "WindLab's server is not answering" messages keep an English
  fallback in app.js for the case where the catalog itself could not be fetched.
- **Tests**:
  - `tests/test_i18n.py`: the catalog is well-formed (keys, placeholders, only the allowed inline markup);
    every key the five scripts and `index.html` use exists and every message is used; the placeholders of
    every message match the parameters passed at the call; a pseudo-localisation pass keeps every placeholder
    and the inline markup and stretches each message by 30 %; a scan of `app.js`, `preview.js`, `viewer.js`
    and `chart.js` **fails if a message is added as a string literal** instead of a catalog key; every text
    node of `index.html` with letters sits inside a `data-i18n` element and **equals its catalog message**
    (so the English in the markup and in the catalog cannot drift apart).
  - `tests/test_js.py` (Node): the page is started twice in the headless DOM, once with `en.json` and once
    with the pseudo-localised catalog; in pseudo mode every `data-i18n` element, every `data-i18n-attr`
    attribute and every text the scripts wrote during the flow (Make this wing, the tour, the glossary, the
    theme, About) must carry the ⟦…⟧ text. This is the "whole page flow" check the requirements ask for, short of a
    real browser.

## How to add a language (1.1)

1. Copy `i18n/en.json` to `i18n/<lang>.json` and translate the values; keep the `{placeholders}` and the
   inline tags exactly. Messages split by a (?) button appear as consecutive `page.*` keys.
2. Make `loadMessages()` pick the file from the browser's language (or a selector in the header) with
   `en.json` as the fallback for missing keys; `t()` already shows `⟦key⟧` for anything missing, so a partial
   translation is visible, never broken.
3. Numbers already follow the catalog's locale (`nf`, `nfInt`); dates in My runs use the browser's locale.

## Not done yet

- **Server-side plain-language text** stays English for now: the geometry check report (`windlab/geometry/upload.py`,
  `step.py`), run warnings and the symmetric-part note (`windlab/app/runs.py`), the expected-error "why" texts
  (`windlab/expected_error.py`, `validation_table.json`), the HTTP error details, the report and CSV headers
  (`windlab/app/report.py`, `runs.py`), and the static demo's fake-server answers (`demo.js`, which mirrors
  the server). The natural home is a second catalog read by the server with the same key style, selected by
  the browser's `Accept-Language`; the report would need its own language choice.
- **Glossary and lessons** are content, not UI text: one JSON per language (`glossary.<lang>.json`,
  `lessons/<id>/lesson.<lang>.json`) chosen by the same locale.
- **Plural forms**: the catalog uses two keys where English needs one/many ("about 1 minute left" /
  "about {m} minutes left", "1 run" / "{n} runs"); a real second language will want ICU-style plural rules.
- **The `page.*` fragments** around (?) buttons could be rejoined with placeholder-based markup
  (`{glossary:camber}`) if translators find the pieces awkward.
